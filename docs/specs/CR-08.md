## Requirement
Track project comments (e.g. the eACC Comments panel) should be sourced from T.A.A. card comments instead of being typed separately. Each T.A.A. comment gets a 'Push to Track' tick box. Only users with role PE, PM and above (Sr PM, Director) see and can use the tick; other staff post comments as normal without the option.

## Why
Director and PM notes (payment status, concerns, decisions) are currently written in Track while day-to-day discussion lives in T.A.A. cards. One comment stream with selective push avoids duplication and keeps Track's project view clean of operational chatter.

## Scope
1. Tick box 'Push to Track' in the T.A.A. comment composer (and on existing comments via edit), visible only for PE/PM/Sr PM/Director roles.
2. Pushed comment appears in the linked Track project's Comments panel with author, role badge, timestamp and a 'from T.A.A.' tag linking back to the card. Card must belong to a project linked to Track (CR-06).
3. Pushed = official record. Once pushed, the comment becomes a project record in Track: it can never be silently removed. Unticking or deleting at source requires a reason and Track shows the comment as 'Withdrawn – <reason>' (greyed, still readable to PM and above, hidden from lower roles). Edits at source create a version history in Track (v1, v2 and so on with diff, author, time); Track always displays the latest version with an 'edited' marker.
4. Filtering on push: @mentions are stripped to plain names (no notification from Track); attachments are not pushed unless explicitly ticked per file; files/text tagged Internal/Confidential on the card cannot be pushed; a preview shows exactly what will appear in Track before confirming.
5. Default OFF for every role, including Director. No 'remember my choice'. Push is a deliberate per-comment action.
6. Full audit log (push, edit, withdraw) retained with the project.
