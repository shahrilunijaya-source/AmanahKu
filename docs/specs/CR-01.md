## Requirement
Amanahku work items (Tasks, Assignments, Adhoc) must sync to Google Calendar, and Google Calendar events must sync back into Amanahku. Sync in both directions (vice versa).

## Why
Staff currently maintain due dates in two places. Overdue items (e.g. +7 days) are not visible in the calendar people actually check daily. One source of truth reduces missed deadlines.

## Scope
Amanahku to Google Calendar: create / update / delete a calendar event whenever a card with a due date is created, edited, moved between columns, or archived. Event title = card title; description = type, project tag, priority, assignees, link back to the card.

Google Calendar to Amanahku: events created or changed in Google Calendar (e.g. meetings, client discussions) appear in the user's My Work view and can be converted into a Task/Assignment. Date changes in Calendar update the card due date.

## Rules
1. Dedicated calendar: Amanahku creates a separate 'Amanahku' calendar in each user's Google account; work items sync only to that calendar, never to the primary. Only events the user explicitly imports (or events on the Amanahku calendar) flow back. Personal primary-calendar events never become work records automatically.
2. Integration ID: every synced object carries a unique integration ID (card_id to google_event_id) stored on both sides; sync is idempotent. Reconnecting matches on ID and never duplicates.
3. Deletion: deleting an event in Google marks a linked T.A.A. Event 'Cancelled (calendar)' and notifies the owner. It never deletes the card. For a work item, deleting its calendar entry only removes the visibility entry; the card and its locked due date are untouched and the entry is re-created on next sync. Deleting/archiving a card removes only the Amanahku-calendar event.
4. Conflict: no 'last edit wins'. Amanahku is the source of truth for title, project, assignees and for work-item due dates (locked, see Date & Calendar Rules); Google date/time changes are accepted only for Event items. Each sync writes a version stamp and ignores echoes of its own update (loop protection); Event conflicts within 60s are queued for the owner to resolve.
5. Recurring events: synced as one card per occurrence for the next 30 days, linked to the series ID; editing the series updates future occurrences only.
6. Cancelled events: Google 'cancelled' status maps to card marked Cancelled, not Done.
7. Multiple calendars: only the Amanahku calendar syncs both ways; the user may optionally tick other calendars as read-only (shown on dashboard, no card created).
8. Cards with 'No due date' are not synced until a date is set. Only the Primary Owner's calendar receives the event; helpers get it as optional guests.
9. Retry protection: failed syncs retry with backoff (max 5), then surface in a 'Sync issues' list; no partial writes.

## Auth
Google OAuth per user (Google Workspace account). Connect / disconnect from user profile settings. Store refresh token securely; handle token expiry gracefully.

## Acceptance
1. Set a due date on a card, event appears in Google Calendar within 1 min.
2. Change the date in Google Calendar, card due date updates in Amanahku.
3. Delete event in Google, card shows Cancelled (calendar), card still exists.
4. Disconnect then reconnect, no duplicate events or cards.
5. Edit a card title 5 times quickly, exactly one event, no ping-pong updates.
6. Personal event on primary calendar, no card created.
7. Move a Task's calendar entry, T.A.A. due date unchanged, calendar entry snaps back.

## Notes / Risks
Google API quota limits; timezone (Asia/Kuala_Lumpur) enforced; store refresh tokens encrypted; sync log retained 90 days for audit.
