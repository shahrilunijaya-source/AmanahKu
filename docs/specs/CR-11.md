## Requirement
On the Events screen (town halls, training, holidays, socials), the people field must be Attendees, not an assignee. Tagging attendees pushes the event to each attendee's T.A.A. board and Google Calendar. After the event, attendees can post photos, comments and lessons learnt on the event page, make learning fun again.

## Why
Today an event is just a listing with @mentions (e.g. @Kussairi @Syakir on 'Cybersecurity in the Age of NeoCloud'); it never reaches the attendee's work board or calendar, and nothing is captured afterwards. External trainings paid by the company should leave a shareable record for everyone.

## Scope
1. Attendees field (multi-select staff picker) replaces @mention text; RSVP/Register status shown per attendee (Going / Registered / Attended).
2. Sync: each attendee gets an Event card on their T.A.A. board (type Event, date/time, location, host, link) and a Google Calendar event with location and RSVP, via CR-01. Removing an attendee removes both.
3. Post-event page (unlocks after end time): photo gallery (multi-upload, captions), comments thread with reactions, and a Lessons learnt section, one entry per attendee (What I learnt / How we can use it / Links to slides or materials). Others can react and reply.
4. Lessons learnt feed into Knowledge (searchable) and can be tagged to a project. Optional: badge/points per contribution to encourage sharing.
5. Event creator or PM and above can set attendees; attendees can add their own photos/lessons only.
6. Dashboard visibility: an 'Events' card on everyone's Dashboard (same prominent style as CR-13) showing upcoming events with who is attending (avatars, 'Kussairi & Syakir are at HPE AI Developer Days today'), and recently completed events with a photo strip and latest lessons learnt. Clicking opens the event page. Makes it fun, everyone sees where colleagues are going and what they brought back.
