## Requirement
Amanahku must become the single project master. The 'Add project' form in Amanahku currently holds only Code, Project name, Order and Category, so users must re-key everything again in Track (Project Details / Project Info). Extend Amanahku's project record with the full details; when Track links to an Amanahku project, all fields are pulled automatically and Track only requires WBS (baseline import) and team.

## Why
Double entry between Amanahku and Track creates mismatched data (client name, contract value, dates) and wasted time. One master record keeps HR/timesheet, T.A.A. and project tracking consistent.

## Scope

**A. Amanahku project form** – add fields: Client, Contract Value (MYR), Status (Planning / Active / Closed), Procurement method, Contractor, Bond Value, Bond Submitted (date), Letter of Acceptance (date/ref), Company Agreement (date/ref), Contract Start, Contract End, Google Drive link, Assigned PM, Assigned PE. Existing fields kept: Code, Project name, Order, Category.

**B. Track integration:** selecting a project in 'Link AmanahKu Project' auto-fills Category, Client, Project Name, Contract Value, Tender/Contract details, PM and PE as read-only (with 'Edit in Amanahku' link). Project Info card in Track reads live from Amanahku (Start/End remain set on baseline upload).

**C.** Track only asks for: Baseline Import (WBS from MS Project xlsx/xml or template) and Team assignment.

**D. Sync:** edits in Amanahku reflect in Track; Track cannot overwrite master fields. API/pull model, same as timesheet integration.

**E. Data governance (so history is never rewritten):**
1. Unique project code, immutable once created (e.g. KPT-RMS-2026-01); used as the integration key.
2. Version history, every master change creates a new version (who, when, old to new, reason); versions viewable in both Amanahku and Track.
3. Effective date on each version; Track reports (weekly, monthly, money-out) read the version effective for that reporting period, never the latest. Re-generating an old report reproduces the old figures.
4. Contract variation records, contract value and contract dates cannot be edited in place; changes are entered as a Variation (VO no., date, reason, delta, attachment) which creates the new version. Original value always retained.
5. Approval, variations to contract value, contract start/end and client require Director approval before the version becomes effective; pending variations shown as 'Awaiting approval'.
6. Field-level permissions, Finance/Director: contract value, bond, LOA, agreement; PM: PM/PE, status, Drive link, procurement; HR: none; everyone else read-only.
7. Closed-project lock, status Closed freezes the master; reopening requires Director with reason.

## Acceptance
1. Create a project in Amanahku with full details, it appears in Track's search list.
2. Link it in Track, Project Details and Project Info are pre-filled, no manual entry.
3. Raise a contract-value variation dated 1 Oct, 'Awaiting approval'; after Director approval, Track's October report shows the new value while the August weekly report still shows the old value.
4. Track project can be saved with only Amanahku link + baseline + team.
5. Existing projects migrate as version 1 with effective date = creation date.
6. PM tries to edit contract value, blocked; Finance tries to edit PM, blocked.
7. Closed project, all fields read-only until Director reopens with reason.
