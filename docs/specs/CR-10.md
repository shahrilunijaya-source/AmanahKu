# CR-10 – TOT Tindakan Susulan to T.A.A. with Next-TOT Due Date

| Field | Value |
|---|---|
| Module | Learning / T.A.A. |
| Priority | Medium |
| Tracker status | Open |
| Owner | Shazwan |
| Target | 11 Sep 2026 |
| Run status | In run, session S12. Next TOT date computed internally, not read from Google Calendar |

## Requirement
Inside a TOT session (CR-09), the Tindakan Susulan table (Bil / Tindakan / Pemilik / Sasaran) must be editable in-app. Each action can tag an assignee (and helpers) directly, and on save it automatically creates a card on the assignee's T.A.A. board. Default due date = next month's TOT date.

## Why
Actions recorded in the Nota Perbincangan PDF (e.g. Rubmin's PostgREST PoC, Syafiq's centralised guardrail) are not tracked anywhere after the session, so follow-through depends on memory. Auto-creating T.A.A. cards makes them visible, overdue-able, and reportable at the next TOT.

## Scope
1. Tindakan table in the session page: action text, Pemilik (staff picker, multi, first = Primary Owner, rest = tagged helpers), Sasaran (date; defaults to next TOT Saturday, editable until first save; locked once the T.A.A. Task is created, Date & Calendar Rules 6).
2. On save, T.A.A. card of type Task, title = action text, project tag = 'TOT <month>', label 'TOT Action', link back to the session/slot. Helpers appear as tagged (CR-04).
3. Card status syncs back: Tindakan row shows Open / In Progress / Done from T.A.A.
4. Next session page shows a 'Tindakan bulan lepas' block listing last session's actions and status, for review at the start of the meeting.
5. Editing/deleting an action updates or archives the card. Only Pengerusi / PM and above can add or edit Tindakan.

## Acceptance
1. In the Ogos 2026 session, add Tindakan 1 with Pemilik = Rubmin, helper Nabil, card appears on Rubmin's board (Nabil tagged) with due = September TOT date.
2. Change Sasaran before saving, allowed; after save, Sasaran and Task due date are locked.
3. Rubmin moves card to Done, Tindakan row shows Done.
4. September session opens with last month's 4 actions and their status.

## Dependencies
CR-09 (session model), CR-04 (tagged label), CR-01 (calendar sync for next TOT date). In the autonomous run CR-01 is deferred, so the next TOT Saturday is computed from the session schedule instead.
